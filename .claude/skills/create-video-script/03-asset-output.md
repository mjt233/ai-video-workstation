# 资产原型输出

## 集数（Episode）概念

项目支持多集（多集动画/系列视频）设计。每集拥有独立的分镜序列。

- 集数从 1 开始编号
- 每集的分镜独立编号，均从 1 开始
- 分镜资产存放在 `prompt/scene/{集数}/{分镜编号}/` 目录下
- 所有脚本工具通过 `--episode`（或 `-e`）参数指定操作哪一集的分镜，默认值为 `1`（详见 [`04-script-tools.md`](./04-script-tools.md)）
- 同一集的场景、角色资产可在各集之间复用，无需重复创建

## 多项目支持

`design/` 目录支持同时维护多个剧本项目，每个项目是一个独立的目录：

```
design
  ├── {项目名称}/          # 如 "古人在现代"
  │   ├── overview.md
  │   └── prompt/
  │       ├── character/...
  │       ├── stage/...
  │       └── scene/
  │           └── {集数}/
  │               └── {分镜编号}/
  │                   ├── overview.json
  │                   ├── stage.json
  │                   ├── script.json
  │                   └── prompt.md
  └── {另一个项目}/
      └── ...
```

- 每个项目目录下必须有 `overview.md` 文件（脚本工具通过此文件识别项目）
- 脚本工具通过 `--project`（或 `-p`）参数指定操作哪个项目，默认使用第一个检测到的项目
- 使用 [`validate.py --list-projects`](./04-script-tools.md#列出项目) 列出所有可用项目

## 约定

角色名和场景名文件夹名称均使用中文命名（外国人 或 外国地名 除外）

## 总流程

1. 输出总览并让用户确认是否需要调整
2. 用户确认总览后，生成细分的原型描述资源

```markdown
- 参考素材：{...}

{200字以内的剧情概要}

| 角色名 | 性别 | 年龄 | 性格关键词 |
|--------|------|------|-----------|
| {...}  | {...}| {...}| {...}      |

| 场景 | 时间 | 角度 | 天气 | 子场景 |
|------|------|------|------|--------|
| {...}| {...}| {...}| {...}| {...}   |
```

### 前置确认事项

在总览阶段（`overview.md`），需包含并让用户确认以下内容：

- 目标受众
- 情感基调
- 色彩基调
- 画面比例与分辨率
- 参考素材（如有）
- 所有角色和场景的总览

## 输出目录结构

所有资产均输出到用户当前工作目录的 `design` 下，每个项目独立一个子目录：

```
design
  └── {项目名称}                     # 剧本项目目录，如"古人在现代"
      ├── project.json              # 项目结构化配置（分辨率、画面比例等）
      ├── overview.md                # 总览（含前置设定、角色总览、场景总览）
      └── prompt
          ├── character
          │   └── {角色名}
          │       ├── overview.md    # 角色总览（姓名、性格、背景）
          │       ├── appearance.md  # 外貌图像描述（结构化，适配 qwen-image）
          │       └── voice.md       # 声线描述（结构化，适配 qwen-3-tts）
          ├── stage
          │   └── {场景名}
          │       └── {完整场景标签}.md  # 含场景画面描述、主色调
          └── scene
              └── {集数}             # 从1开始编号
                  └── {分镜编号}     # 从1开始编号
                      ├── overview.json  # 分镜内容总览（title/beat/visual/camera/duration/mood）
                      ├── stage.json     # 场景原型JSON（引用stage + 角色 + 组合prompt）
                      ├── script.json    # 台词原型JSON
                      └── prompt.md      # 图生视频模型提示词（LTX-2.3）
```

### voice.md 模板

用1-3句自然语言描述声线，不分类不分点，直接给出整体听觉感受：

```markdown
体现撒娇稚嫩的萝莉女声，音调偏高且起伏明显，语速较快咬字略含糊，句尾常带上扬的尾音。整体营造出黏人、做作又刻意卖萌的听觉效果，给人以娇气又带点小任性的印象。
```

## 分镜资产输出

分镜资产在总览确认、角色和场景原型都输出完成后生成。每个分镜对应一个独立的视频片段（shot）。

> **工具约束：** `overview.json` / `stage.json` / `script.json` **禁止手写编辑**，必须通过 [`04-script-tools.md`](./04-script-tools.md) 中的 Python 脚本增删改；`prompt.md` 可直接写入文件。

**分镜生成流程：**

1. 确定当前操作的集数（集数从 1 开始编号，每集分镜独立编号）
2. 根据剧情拆解出连续的叙事节拍，确定该集分镜总数
3. 为每个分镜分配：引用的场景、登场的角色、发生的动作/对白
4. 确保每个分镜引用的场景 asset 已存在、角色 asset 已存在
5. 用 [`set_shot_overview.py`](./04-script-tools.md#分镜总览overviewjson) 写入分镜总览 `overview.json`（含 `duration` 秒数）
6. 用 [`add_stage.py`](./04-script-tools.md#场景管理stagejson) 写入场景组合 `stage.json`（有角色合成 / 直接引用基础场景两种模式）
7. 用 [`add_script.py`](./04-script-tools.md#台词管理scriptjson) 写入台词 `script.json`（无对白则跳过，保持 `[]`）
8. 写入图生视频提示词 `prompt.md`
9. 该集分镜写完后，运行 [`validate.py`](./04-script-tools.md#完整性校验) 做完整性校验

### 分镜内容总览（overview.json）

> **写入方式：** 使用 [`set_shot_overview.py`](./04-script-tools.md#分镜总览overviewjson) 创建或更新字段。不要直接编辑 JSON 文件。

```json
{
  "title": "{分镜标题}",
  "beat": "{该分镜在剧情中承担的作用和要传达的信息}",
  "visual": "{角色在场景中的位置、朝向、动作、镜头角度等}",
  "camera": "{固定/推近/拉远/平移/环绕/跟随等}",
  "duration": 5,
  "mood": "{该分镜段落的情感色彩}"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `title` | string | 分镜标题 |
| `beat` | string | 叙事节拍 |
| `visual` | string | 画面描述 |
| `camera` | string | 镜头运动 |
| `duration` | number | 时长（秒，**正整数**，须 `> 0`；默认 `5`） |
| `mood` | string | 情绪基调 |

> 注意：分镜总览使用 `overview.json`，**不再使用** `overview.md`。项目级 / 角色级 `overview.md` 保持不变。

### 衍生变体（角色 / 场景）

当基础角色外观或基础场景图需要局部变化（如「门已打开」「披风被风吹起」「侧身站立」），应创建**衍生变体**，而不是复制整套基础资产。

**目录约定（不出现在资产浏览器树中，仅在角色/场景详情中管理）：**

```
prompt/character/{角色名}/variants/{变体id}.json
assert/character/{角色名}/variants/{变体id}.jpg

prompt/stage/{场景名}/variants/{完整场景标签}/{变体id}.json
assert/stage/{场景名}/variants/{完整场景标签}/{变体id}.jpg
```

**变体 meta JSON 示例：**

```json
{
  "id": "门已打开",
  "desc": "图像1基础上，将正门改为打开状态，门内可见商场内部灯光",
  "baseImage": "assert/stage/现代商场/现代商场-白天-平视-正门入口.jpg",
  "createdAt": "2026-07-29T00:00:00.000Z"
}
```

| 字段 | 说明 |
|------|------|
| `id` | 变体名称，目录/文件名与之一致 |
| `desc` | **图片编辑**工作流的编辑描述（相对基础图的变化） |
| `baseImage` | 可选，默认指向基础外观图/场景图 |

**分镜引用语法：**

| 类型 | 基础引用 | 衍生变体引用 |
|------|----------|--------------|
| 场景 | `{场景名}/{完整场景标签}` | `{场景名}/{完整场景标签}@{变体id}` |
| 角色 | `{角色名}` | `{角色名}@{变体id}` |

示例：

- 基础场景：`现代商场/现代商场-白天-平视-正门入口`
- 场景变体：`现代商场/现代商场-白天-平视-正门入口@门已打开`
- 角色变体：`陈书文@侧身`

> 变体图片需用户手动生成或通过一键生成（资产类型 `variant-edit`）生成；创建变体时只写入 meta，不预生成图片。  
> 分镜 `stage.json` 的 `基础场景` / `登场角色` **均可选择衍生变体**。

### 场景组合JSON（stage.json）

> **写入方式：** 使用 [`add_stage.py`](./04-script-tools.md#场景管理stagejson) 添加条目；修改用 [`update_stage.py`](./04-script-tools.md#场景管理stagejson)，删除用 [`remove_stage.py`](./04-script-tools.md#场景管理stagejson)。不要直接编辑 JSON 文件。

stage.json 描述的是**静态关键帧**，作为图生视频模型的参考帧输入。数组中的每个元素定义一帧的画面构成，按顺序对应视频的不同时间点：

- **1 个元素**：仅首帧参考
- **2 个元素**：首帧 + 尾帧参考
- **3 个元素**：首帧 + 中帧 + 尾帧参考

```json
[
  {
    "基础场景": "{场景名}/{完整场景标签}",
    "登场角色": [
      "{角色名1}"
    ],
    "prompt": "图像1为背景：{场景画面概述}；图像2在{场景地标/区域}，{相对位置}，身体朝向{参考点}，面部朝向{参考点}，{静态动作/姿势}；其他画面细节补充"
  }
]
```

双人示例（须写清人物之间的位置关系与朝向）：

```json
[
  {
    "基础场景": "{场景名}/{完整场景标签}",
    "登场角色": ["{角色名1}", "{角色名2}"],
    "prompt": "图像1为背景：{场景画面概述}；图像2站在{场景地标}左侧，身体朝向图像3，面部朝向图像3；图像3站在图像2右侧约一步距离、靠近{场景地标}，身体朝向图像2，面部微侧向镜头；{静态动作/姿势}"
  }
]
```

直接引用基础场景（不做角色合成/画面修改）时，`登场角色` 与 `prompt` 均留空：

```json
[
  {
    "基础场景": "{场景名}/{完整场景标签}",
    "登场角色": [],
    "prompt": ""
  }
]
```

直接引用**同集上一分镜最后一个场景图**时，使用关键字 `prev`（仅直接引用，不可叠角色/prompt）：

```json
[
  {
    "基础场景": "prev",
    "登场角色": [],
    "prompt": ""
  }
]
```

> **约束：**
> - `基础场景` **必须非空**，可为：基础场景 `{场景}/{标签}`、衍生变体 `{场景}/{标签}@{变体id}`，或关键字 `prev`
> - `prev` 表示同集上一分镜 `stage.json` **最后一项**对应的分镜场景图 `assert/scene/{集}/{上一镜}/stage/{末下标}.jpg`；**第 1 个分镜禁止**；**仅允许直接引用**（`登场角色` 与 `prompt` 必须为空），生成时由引擎复制上一分镜最后场景图
> - `登场角色` 与 `prompt` **同时为空**时，表示**直接引用**（基础场景图 / 场景变体图 / 上一分镜最后场景图），不做任何修改。生成分镜场景图时，由**工作流调度引擎**将对应 assert 图 **复制**为独立资产 `assert/scene/{集}/{镜}/stage/{index}.jpg`（不调用图像编辑）
> - 需要合成/修改画面时：`prompt` 必须非空；若有 `登场角色`，可为 `{角色名}` 或 `{角色名}@{变体id}`，对应角色目录/变体须存在，数组长度不超过 2；**不可**对 `prev` 做合成
> - 不允许「仅有登场角色但 prompt 为空」：有角色合成时必须提供 prompt
> - `prompt` 中**不应包含视频运镜描述**（推拉摇移等），运镜描述放在 `prompt.md` 中；由于已提供了原图，避免对原背景画面、人物着装外貌重复描述
> - prompt 字段中，"图像1"代表基础场景（stage 的渲染图），"图像2"代表第一个登场角色（角色正面全身图），"图像3"代表第二个登场角色。提示词需引导图像编辑模型将角色合成到场景中
> - **有登场角色时，`prompt` 必须写清空间关系与朝向**（合成质量关键，缺一不可）：
>   1. **人物位置关系** — 说明角色相对场景地标的位置，以及角色之间的相对位置（如「图像2在柜台前偏左，图像3在图像2右侧约一步」）；单人时至少写清相对场景特征的落点
>   2. **面部与身体朝向** — 分别说明面部、身体朝向；**必须以人或场景中的特征为参考点**（如「身体朝向图像3」「面部朝向中央扶梯」「身体朝向柜台，面部微侧向镜头」），禁止仅用无锚点的抽象方位（如单独写「面向左侧」「背对镜头」而不说明朝向何物）
> - 当需要首尾帧时，两个元素的 `基础场景` 和 `登场角色` 通常相同，但 `prompt` 描述的角色姿势/位置/表情不同

### 台词原型JSON（script.json）

> **写入方式：** 使用 [`add_script.py`](./04-script-tools.md#台词管理scriptjson) 添加台词；删除用 [`remove_script.py`](./04-script-tools.md#台词管理scriptjson)。不要直接编辑 JSON 文件。

```json
[
  {
    "角色名": "{角色名1}",
    "台词": "{角色说的台词内容}",
    "情绪": "{说这句台词时的情绪状态，如：平静、激动、犹豫、愤怒等}"
  }
]
```

> 说明：数组按台词出现的先后顺序排列。如果该分镜为纯画面无对白，则留空数组 `[]`。角色名必须在对应的分镜 stage.json 的 `登场角色` 中声明。

### 图生视频模型提示词（prompt.md）

LTX-2.3 模型的提示词，纯文本格式（无 Markdown 标题），仅需一段正向提示词：

```text
{一段连贯的英文描述，包含：场景环境、角色描述、角色动作（含台词原文）、镜头运动、动态氛围}
```

> **约束要点：**
> - **纯文本** — prompt.md 不包含任何 Markdown 标题（如 `# 分镜XX`），直接以提示词内容开头
> - **仅正向提示词** — 不包含负面提示词（negative prompt）和生成参数（guidance_scale、帧数等）
> - **英文撰写** — LTX-2.3 基于英文训练，提示词使用英文
> - **运镜描述放在 prompt.md** — 视频的镜头运动（推/拉/摇/移/跟随等）写在此处，不在 stage.json 的 prompt 中出现
> - **台词嘴型** — 如果该分镜在 `script.json` 中有台词，必须将角色的**台词原文**插入到提示词的动作描述中，用英文引号包裹，引导模型生成与台词匹配的嘴型动作。例如：`The scholar shouts in panic: "这……这是何等妖法？！"`。多个角色先后说话时按对话顺序嵌入对应的台词原文
> - **结构建议**：`[场景环境], [角色描述], [动作描述及台词原文], [镜头运动], [氛围/光照]`。保持简洁聚焦，避免过于复杂的场景描述
> - **首中尾帧配合**：如果运镜涉及场景切换或大幅画面变化，应在 stage.json 中定义首帧/中帧/尾帧引导画面，prompt.md 中的动态描述应与关键帧序列相匹配
