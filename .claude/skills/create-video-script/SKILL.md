# 创建视频剧本全局大纲说明

## 前置设定

在进入具体内容设计之前，先通过问答方式引导用户确立项目的顶层定位。

**流程规范：**

1. 从用户给出的需求描述中提取已知信息，对仍有多个可能性或不确定的项，通过 `question` 或 `ask_user` 工具让用户做选择
2. 每个问题应提供 2-3 个明确选项，选项需有清晰差异和简短说明，让用户能快速决策
3. 需引导用户确认的决策点按以下顺序逐一询问：

### 决策顺序

以下决策点按顺序推进，但每个决策的**选项内容不局限于文档中列举的例子**，根据用户需求发散创作：

1. **目标受众** — 明确视频的目标观众群体
   - 影响：内容复杂度、叙事节奏、主题深度
   - 根据项目题材发散：不限于"年龄段"划分，也可以是特定兴趣群体、职业群体等

2. **情感基调** — 故事的整体情绪底色，不同段落可有变化
   - 影响：所有后续设计的情绪导向
   - 可单一可混合，不限于常见标签，根据题材发散创作

3. **色彩基调** — 整体视觉的色彩倾向
   - 影响：指引后续所有场景的主色调设计
   - 可结合情感基调发散，也可以抽象概念表达（如"旧照片的黄"、"廉价日光灯的冷白"等）

4. **美术风格** — 视觉表现风格
   - 影响：角色设计、场景渲染的方向
   - 可结合AI模型能力发散，不局限于常见风格标签

5. **画面比例与分辨率** — 视频的横竖屏格式和分辨率
   - 影响：场景构图方式、角色在画面中的位置设计、文字排版空间
   - 常见选择：
     - 横屏 16:9（1920×1080 或 1280×720）— 适合PC/电视播放，故事感和电影感强
     - 竖屏 9:16（1080×1920 或 720×1280）— 适合抖音/快手/小红书等短视频平台
     - 方形 1:1（1080×1080）— 适合社交平台信息流
   - 不限于上述常见选择，可根据发布平台发散

6. **剧情方向** — 在确定以上基调后，准备 2-3 个不同的剧情概念方向供用户选择
   - 每个方向需包含一句话梗概和核心看点说明
   - 方向之间应有明显差异，覆盖不同切入点
   - 用户选定后进入剧情细化

其他决策：根据用户的回答你需要再提问1到2个你认为需要考虑或建议的决策方向

### 参考素材

用户可提供风格参考图、参考影片链接或氛围参考板链接，附着在 `overview.md` 中。

## 内容设计

### 内容设计概要

创建视频剧本全局大纲时，需要按顺序生成以下元素：

- 视频美术风格
- 剧情概要简介
- 世界/时代背景设定
- 角色设计
- 拍摄场景设计
- 分镜设计（Storyboard）

### 视频美术风格

如：日本二维动画风格、3D动画风格、写实、简约手绘动画、油墨画风格等

### 剧情概要简介

需要特别注意交待以下内容：

- 故事主体：如xx家族、xx公司、某个人等
- 事件概要
- 情感基调与色彩基调在剧情中的体现

约束：字数在200字以内

### 世界/时代背景设定

故事所在世界的详细设定：

- 时代背景：如中国90年代农村、充满魔法的异世界、科技发达的未来、现代都市、远古时代古村落等
- 世界观规则：如有特殊规则（魔法体系、科技限制等）需说明
- 氛围关键词：如"破败但温暖"、"繁华而冷漠"等

### 角色设计

需要包含以下内容：

- 姓名
- 性别
- 性格
- 背景
- 外貌图像描述 —— 适配 qwen-image 文生图模型，采用结构化描述：
  - 年龄、性别
  - 身高体型
  - 发型发色
  - 脸型、五官特征
  - 衣着风格（颜色、款式、材质）
  - 气质关键词
  - 参考风格倾向（如"类似吉卜力风格的人物设计"）
- 声线音色描述 —— 适配 qwen-3-tts 语音合成，用一两句话自然描述，涵盖年龄感、音色特征、语速、语调特点即可，不分类不分点。

### 拍摄场景设计

人物将在拍摄场景中登场演出，需要设计详细的场景描述。场景构图需考虑到已确定的画面比例（横屏/竖屏）。

**画面比例对场景设计的影响：**
- **横屏 16:9**：画面宽阔，适合展示环境全貌、多人同框、横向移动。构图时注意左右空间的利用。
- **竖屏 9:16**：画面纵向延伸，适合展示高度层次（前景/中景/背景堆叠）。构图时注意上下空间的利用，角色居中偏下。
- **方形 1:1**：画面紧凑，适合居中构图，信息集中。

场景设计包括：

- 场景位置标签：
  格式为：`{场景地点}-{时间}-{拍摄角度}-{氛围/天气}-{子场景}-{子场景...}`
  
  子场景是可选的且可叠加。新增"氛围/天气"维度示例：
  - `汽车总站夜市-中午-仰拍-晴-总站大门`
  - `汽车总站夜市-夜晚-平视-雨-中央过道`
  - `汽车总站夜市-黄昏-俯视-阴-中央过道-被炸毁`
  - `汽车总站夜市-夜晚-平视-雾-中央过道-繁荣`
  
  标签要求：存在2个或以上子场景时，必须设计前一个子场景的描述。

- 场景画面描述：
  - 时间与视角角度
  - 氛围/天气状态
  - **主色调/色彩氛围**（如：暖黄灯光为主调、暗蓝色冷调、高饱和霓虹色等）
  - 尽可能详细描述完整场景画面
  - **约束：场景描述中不能包含具体角色的行为动作或外貌描述**，场景是纯粹的背景环境（仅包含光线、布局、色彩、道具等）。角色由后续的图片编辑流程独立合成到场景中。

### 分镜设计（Storyboard）

在场景和角色设计完成后，进入分镜设计环节。分镜是衔接"静态资产设计"与"视频生成"的关键桥梁，每个分镜对应一个独立的视频片段（shot），用于 LTX-2.3 图生视频模型生成。

**分镜设计原则：**

1. **按叙事顺序拆分** — 将剧情按时间线拆分为多个连续的 shot，每个 shot 聚焦一个明确的叙事节拍（action beat）
2. **一个分镜一个动作** — 每个 shot 只描述一个连贯的动作或状态变化，不要在一个分镜内堆叠多个不连续的事件
3. **角色数量限制** — 每个分镜画面中登场角色不得超过 2 个（LTX-2.3 模型多人交互质量有限），群戏通过交替剪辑解决
4. **场景引用** — 每个分镜必须引用已在 `design/prompt/stage/` 下定义的场景资产，确保背景一致性
5. **动线设计** — 考虑角色在场景中的进出路径和位置变化，为视频生成提供运动逻辑

**分镜与场景的关系：**

- 一个"场景"（stage）是固定的环境背景（如"奶茶店前"），一个场景可以承载多个分镜
- 每个分镜需要指定在哪个场景下发生、哪些角色登场、以及他们的动作/台词
- 不同分镜可以复用同一个场景，但通过角色位置、镜头角度、时间变化制造差异

**LTX-2.3 图生视频提示词要点：**

LTX-2.3 是基于图像条件的视频生成模型，提示词需要特别关注：
- **运动描述** — 清晰描述主体动作（谁在做什么），避免静态描述
- **镜头运动** — 如推近（zoom in）、拉远（zoom out）、平移（pan left/right）、上摇（tilt up/down）、跟随（follow）
- **持续时间** — 可建议生成帧数或时长（如 2 秒、4 秒）
- **一致性** — 角色外貌、衣着、场景光照需与 existing assets 保持一致
- **负面提示** — 可补充不希望出现的元素（如模糊、变形、闪烁）

## 资产原型输出

### 集数（Episode）概念

项目支持多集（多集动画/系列视频）设计。每集拥有独立的分镜序列。

- 集数从 1 开始编号
- 每集的分镜独立编号，均从 1 开始
- 分镜资产存放在 `prompt/scene/{集数}/{分镜编号}/` 目录下
- 所有脚本工具通过 `--episode`（或 `-e`）参数指定操作哪一集的分镜，默认值为 `1`
- 同一集的场景、角色资产可在各集之间复用，无需重复创建


### 多项目支持

`design/` 目录支持同时维护多个剧本项目，每个项目是一个独立的目录：

```
design
  ├── {项目名称}/          # 如 "古人在现代"
  │   ├── overview.md
  │   └── prompt/
  │       ├── character/...
  │       ├── stage/...
  │       └── scene/
  │           └── {集数}/
  │               └── {分镜编号}/
  │                   ├── overview.md
  │                   ├── stage.json
  │                   ├── script.json
  │                   └── prompt.md
  └── {另一个项目}/
      └── ...
```

- 每个项目目录下必须有 `overview.md` 文件（脚本工具通过此文件识别项目）
- 脚本工具通过 `--project`（或 `-p`）参数指定操作哪个项目，默认使用第一个检测到的项目
- 使用 `python .../validate.py --list-projects` 列出所有可用项目

角色名和场景名文件夹名称均使用中文命名（外国人 或 外国地名 除外）

### 分镜资产输出

分镜资产在总览确认、角色和场景原型都输出完成后生成。每个分镜对应一个独立的视频片段（shot）。

**分镜生成流程：**

1. 确定当前操作的集数（集数从 1 开始编号，每集分镜独立编号）
2. 根据剧情拆解出连续的叙事节拍，确定该集分镜总数
3. 为每个分镜分配：引用的场景、登场的角色、发生的动作/对白
4. 确保每个分镜引用的场景 asset 已存在、角色 asset 已存在
5. 生成分镜内容总览、场景组合 JSON、台词 JSON、视频模型提示词

#### 分镜内容总览（overview.md）

```markdown
# 第{集数}集 分镜 {分镜编号} - {分镜标题}

## 叙事节拍
{该分镜在剧情中承担的作用和要传达的信息}

## 画面描述
{描述分镜的画面构成：角色在场景中的位置、朝向、动作、镜头角度等}

## 镜头运动
{描述镜头运动方式：固定/推近/拉远/平移/环绕/跟随等}

## 时长参考
{建议的视频时长或帧数，如"约3秒（72帧）"}

## 情绪基调
{该分镜段落的情感色彩}
```

#### 场景组合JSON（stage.json）

```json
[
  {
    "基础场景": "{场景名}/{完整场景标签}",
    "登场角色": [
      "{角色名1}"
    ],
    "prompt": "图像1为背景：{场景画面概述}；图像2为{角色名1}：{角色外貌概述，引用角色appearance.md中的关键描述}；{角色名1}在{场景画面概述}中{动作描述}。镜头{运动方式}"
  }
]
```

> 说明：数组支持多个元素用于一个分镜内需要画面拼接/过渡的情况。`基础场景`的值必须在 `design/prompt/stage/{场景}/{完整场景标签}.md` 中存在对应的资产文件。`登场角色`必须在 `design/prompt/character/{角色名}` 下存在资产文件，且数组长度不超过2。
>
> prompt 字段中，"图像1"代表基础场景（stage的渲染图），"图像2"代表第一个登场角色（角色正面全身图），"图像3"代表第二个登场角色。提示词需引导图像编辑模型将角色合成到场景中，并描述整体画面的动态效果。

#### 台词原型JSON（script.json）

```json
[
  {
    "角色名": "{角色名1}",
    "台词": "{角色说的台词内容}",
    "情绪": "{说这句台词时的情绪状态，如：平静、激动、犹豫、愤怒等}"
  }
]
```

> 说明：数组按台词出现的先后顺序排列。如果该分镜为纯画面无对白，则留空数组 `[]`。角色名必须在对应的分镜 stage.json 的 `登场角色` 中声明。

#### 图生视频模型提示词（prompt.md）

LTX-2.3 模型的提示词，纯文本格式（无 Markdown 标题），仅需一段正向提示词：

```text
{一段连贯的英文描述，包含：场景环境、角色描述、角色动作（含台词原文）、镜头运动、动态氛围}
```

> **约束要点：**
> - **纯文本** — prompt.md 不包含任何 Markdown 标题（如 `# 分镜XX`），直接以提示词内容开头
> - **仅正向提示词** — 不包含负面提示词（negative prompt）和生成参数（guidance_scale、帧数等）
> - **英文撰写** — LTX-2.3 基于英文训练，提示词使用英文
> - **台词嘴型** — 如果该分镜在 `script.json` 中有台词，必须将角色的**台词原文**插入到提示词的动作描述中，用英文引号包裹，引导模型生成与台词匹配的嘴型动作。例如：`The scholar shouts in panic: "这……这是何等妖法？！"`。多个角色先后说话时按对话顺序嵌入对应的台词原文
> - **结构建议**：`[场景环境], [角色描述], [动作描述及台词原文], [镜头运动], [氛围/光照]`。保持简洁聚焦，避免过于复杂的场景描述。

### 分镜生成优化指南

#### 叙事拆分策略

将剧情拆分为分镜时，遵循以下策略可提升视频生成质量：

| 策略 | 说明 | 示例 |
|------|------|------|
| **建立镜头** | 每个新场景的第一个分镜，用全景展示环境全貌，无角色或角色较小 | 场景"商场正门入口"首次出现时，先用空镜展示商场外观 |
| **动作拆分** | 一个连续动作拆为"起始→执行→结果"三段，每段一个分镜 | 角色拿起杯子（近景）→ 喝水（特写）→ 放下杯子（中景） |
| **对话交替** | 对话场景中，每个说话者独占一个分镜，辅以对手反应镜头 | A说话（A特写）→ B反应（B中景）→ B说话（B特写） |
| **视线衔接** | 角色看向画外→下一分镜接其所看之物（视线匹配） | 角色惊讶看向右侧 → 切至其看到的画面 |
| **时空跳跃** | 时间/地点跳转处单独一个过渡分镜（可加 dissolve 效果描述） | 白天→黄昏，用一个光影变化的空镜过渡 |

#### LTX-2.3 分镜优化要点

**运动优先：**
- LTX-2.3 对明确的运动描述响应最佳。避免静态画面，每个分镜至少包含一个运动元素（角色动作或镜头运动）
- 描述具体运动而非抽象状态：用"她举起右手挥手"而非"她在打招呼"
- 镜头运动与角色运动方向协调：角色向右走 + 镜头向右平移（pan right）

**角色一致性：**
- 同一角色在不同分镜中的外貌、服装描述必须一致，建议从 `appearance.md` 中提取关键描述直接复用
- 角色服装若跨分镜变化（如换装），需在剧情中明确交代过渡

**场景一致性：**
- 引用同一场景资产时，光照、色调须与场景 `stage.json` 中的色彩氛围描述一致
- 不同分镜使用同一场景时，通过角度、景别、时间变化制造区分，而非改变场景本身

**提示词长度控制：**
- 正向提示词建议控制在 200 字符以内，聚焦核心运动与视觉元素
- 负面提示词保持稳定，建议在项目所有分镜中复用同一组负面提示词

#### 分镜数量建议

| 视频时长 | 建议分镜数 | 每个分镜平均时长 |
|----------|-----------|----------------|
| 15秒以内 | 3-5 个 | 3-5 秒 |
| 15-30秒 | 5-10 个 | 3-4 秒 |
| 30-60秒 | 8-15 个 | 4-5 秒 |
| 60秒以上 | 12-25 个 | 4-6 秒 |

> 分镜越短越容易控制，但过多快速切换会降低叙事连贯性。叙事类视频建议每个分镜不少于 2 秒（约 48 帧 @24fps）。

## 输出自我审查

派出一个干净的子Agent（Sub-Agent），检查本次输出产生的prompt资产是否满足以下约束

- 非外国角色或地名的资产文件夹名称是否为中文
- 场景或角色提示词原型中是否包含对 AI 绘图模型不必要的描述（如人名、文件头元数据）
- 项目 `design/` 下每个项目目录是否包含 `overview.md`（用于脚本自动检测）
- 分镜 `stage.json` 中引用的 `基础场景` 是否在对应项目的 `design/{项目}/prompt/stage/` 下有对应的 `.md` 资产文件
- 分镜 `stage.json` 中引用的 `登场角色` 是否在对应项目的 `design/{项目}/prompt/character/` 下有对应的资产文件夹
- 分镜 `stage.json` 中 `登场角色` 数组长度是否不超过 2
- 分镜 `stage.json` 中 `prompt` 字段是否正确使用"图像1"代表基础场景、"图像2"代表第一个角色、"图像3"代表第二个角色
- 分镜 `script.json` 中出现的 `角色名` 是否在对应分镜的 `stage.json` 的 `登场角色` 中已声明
- 分镜编号是否从 1 开始且连续无跳号（按集分别校验）
