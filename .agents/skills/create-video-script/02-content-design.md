# 内容设计

## 内容设计概要

创建视频剧本全局大纲时，需要按顺序生成以下元素：

- 视频美术风格
- 剧情概要简介
- 世界/时代背景设定
- 角色设计
- 拍摄场景设计
- 分镜设计（Storyboard）

## 视频美术风格

如：日本二维动画风格、3D动画风格、写实、简约手绘动画、油墨画风格等

## 剧情概要简介

需要特别注意交待以下内容：

- 故事主体：如xx家族、xx公司、某个人等
- 事件概要
- 情感基调与色彩基调在剧情中的体现

约束：字数在200字以内

## 世界/时代背景设定

故事所在世界的详细设定：

- 时代背景：如中国90年代农村、充满魔法的异世界、科技发达的未来、现代都市、远古时代古村落等
- 世界观规则：如有特殊规则（魔法体系、科技限制等）需说明
- 氛围关键词：如"破败但温暖"、"繁华而冷漠"等

## 角色设计

需要包含以下内容：

- 姓名
- 性别
- 性格
- 背景
- 外貌图像描述 —— 适配 qwen-image 文生图模型，采用结构化描述：
  - 年龄、性别
  - 身高体型
  - 发型发色
  - 脸型、五官特征
  - 衣着风格（颜色、款式、材质）
  - 气质关键词
  - 参考风格倾向（如"类似吉卜力风格的人物设计"）
- 声线音色描述 —— 适配 qwen-3-tts 语音合成，用一两句话自然描述，涵盖年龄感、音色特征、语速、语调特点即可，不分类不分点。

## 拍摄场景设计

人物将在拍摄场景中登场演出，需要设计详细的场景描述。场景构图需考虑到已确定的画面比例（横屏/竖屏）。

**画面比例对场景设计的影响：**
- **横屏 16:9**：画面宽阔，适合展示环境全貌、多人同框、横向移动。构图时注意左右空间的利用。
- **竖屏 9:16**：画面纵向延伸，适合展示高度层次（前景/中景/背景堆叠）。构图时注意上下空间的利用，角色居中偏下。
- **方形 1:1**：画面紧凑，适合居中构图，信息集中。

场景设计包括：

- 场景位置标签：
  格式为：`{场景地点}/{子区域}`，不编码视角、天气、时间。
  
  示例：
  - `现代商场/正门入口`
  - `现代商场/走廊通道`
  - `现代商场/中央扶梯`
  
  标签要求：同一场景下有 2 个或以上子区域时，每个子区域都要有独立的画面描述。

- 场景画面描述：
  - **主色调/色彩氛围**（如：暖黄灯光为主调、暗蓝色冷调、高饱和霓虹色等）
  - 尽可能详细描述完整场景画面（布局、道具、光线等环境气氛可写在画面描述中，不必拆成独立字段）
  - **约束：场景描述中不能包含具体角色的行为动作或外貌描述**，场景是纯粹的背景环境（仅包含光线、布局、色彩、道具等）。角色由后续的图片编辑流程独立合成到场景中。

## 分镜设计（Storyboard）

在场景和角色设计完成后，进入分镜设计环节。分镜是衔接"静态资产设计"与"视频生成"的关键桥梁，每个分镜对应一个独立的视频片段（shot），用于 LTX-2.3 图生视频模型生成。

> 分镜原则确认后，实际落地资产时按 [`03-asset-output.md`](./03-asset-output.md) 输出；其中 `overview.json` / `stage.json` / `script.json` 须用 [`04-script-tools.md`](./04-script-tools.md) 中的脚本写入，禁止手写 JSON。

> **剧本优先：** 若项目存在剧本（`prompt/script/outline.md` 大纲与 `prompt/script/episodes/{集数}.md` 分集正文），设计某集分镜前**必须先读取该集剧本正文**，叙事节拍、事件顺序与对白以剧本为准；剧本与集数分镜相互独立、可能不存在，读取约定与写入规则见 `script-manager` 技能（[`../script-manager/SKILL.md`](../script-manager/SKILL.md)）。

**分镜设计原则：**

1. **按叙事顺序拆分** — 将剧情按时间线拆分为多个连续的 shot，每个 shot 聚焦一个明确的叙事节拍（action beat）
2. **一个分镜一个动作** — 每个 shot 只描述一个连贯的动作或状态变化，不要在一个分镜内堆叠多个不连续的事件
3. **角色数量限制** — 每个分镜画面中登场角色不得超过 2 个（LTX-2.3 模型多人交互质量有限），群戏通过交替剪辑解决；纯空镜/环境镜头可将 `登场角色` 与 `prompt` 留空，直接引用基础场景
4. **场景引用** — 每个分镜必须引用已在 `design/prompt/stage/` 下定义的场景资产（`基础场景` 不可为空），确保背景一致性
5. **动线设计** — 考虑角色在场景中的进出路径和位置变化，为视频生成提供运动逻辑
6. **合成 prompt 的空间与朝向** — 有登场角色时，`stage.json` 的 `prompt` 必须写清人物相对场景地标/彼此的位置关系，以及面部与身体朝向；朝向须以人或场景特征为参考点（详见 [`03-asset-output.md`](./03-asset-output.md#场景组合jsonstagejson)）

**分镜与场景的关系：**

- 一个"场景"（stage）是固定的环境背景（如"奶茶店前"），一个场景可以承载多个分镜
- 每个分镜需要指定在哪个场景下发生；有角色合成时再声明登场角色与合成 prompt，否则直接引用基础场景图
- 不同分镜可以复用同一个场景，但通过角色位置、镜头角度、子区域制造差异

**LTX-2.3 图生视频提示词要点：**

LTX-2.3 是基于图像条件的视频生成模型，提示词需要特别关注：
- **运动描述** — 清晰描述主体动作（谁在做什么），避免静态描述
- **镜头运动** — 如推近（zoom in）、拉远（zoom out）、平移（pan left/right）、上摇（tilt up/down）、跟随（follow）
- **持续时间** — 可建议生成帧数或时长（如 2 秒、4 秒）
- **一致性** — 角色外貌、衣着、场景光照需与 existing assets 保持一致
- **负面提示** — 可补充不希望出现的元素（如模糊、变形、闪烁）
