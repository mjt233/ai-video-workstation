# 开发指南

> 返回 [总览与定位](./README.md)

## 新增一种节点类型

1. 在 `registry.ts` 注册 `NodePrototype`（端口、resizeable、bodyComponent）。
2. **生成类节点**在原型上声明 `outputExt`（产物固定文件名扩展名，如 `jpg`/`mp4`/`png`/`flac`）——产物展示/按钮文案由 AssetCanvas 按固定路径 + node-info 推导后经 `output` prop 下发，组件内优先读 `props.output`、`config.current` 仅作旧数据回落；加载类节点（`config.assetPath`）无需声明。
3. 新建 `components/canvas/nodes/{Xxx}Node.vue`（卡片主体）。
4. （可选）新建 `components/canvas/editors/{Xxx}Editor.vue` 并挂 `editorComponent`；编辑器根元素不要自己定宽度（面板宽度由 AssetCanvas 统一控制）。
5. `config` 字段与既有节点保持兼容（未知字段不影响读取）。
6. **节点主体不要自行渲染 running/error 遮罩**：loading/错误状态是节点的通用能力，由 `CanvasNodeCard` 按 `status` prop 统一叠加（含「中断」按钮）；生成类节点只要经 `gen.generate` / ffmpeg 同步函数进入 running，即自动获得 loading 展示与中断能力。**例外（唯一）**：AI 文本节点声明 `statusOverlay` 为**空组件**（`() => null`）——节点主体完全自绘运行/错误状态 UI（节点内 Thinking 条 + 「停止」按钮 + 响应区错误红字），画布不渲染任何遮罩；声明空组件仅为让 `CanvasNodeCard` 跳过默认整体阻塞遮罩（默认遮罩会拦截流式输出与节点内控件）。需要同样形态的节点类型按此扩展点自行声明（见 [llm-session.md](./llm-session.md)）。
7. **LLM 会话节点（text-ai）状态机接入约定**：节点内生成经 `stream-state` emit（running/log/taskId → 父级 `gen.beginClientRun`；终态 result{status/patch/rev} → `adoptExternalChange` + `endClientRun`），`isRunning`/`activeTaskId`/`runningLog`/`canvasTarget` 由父级按 `statusByNode` 下发 prop（恢复态同样禁用控件、「停止」可用）；流式输出走 `update:output-view` → `store.viewOnlyUpdate`（**纯内存，不写盘、不入撤销栈**）。

## 测试与验证

- 单元测试：`frontend/src/canvas/*.test.ts`，命令 `cd frontend && npm test`（服务端 `cd server && npm test`）。
- 修改后必须：`npm run typecheck` + `npm run lint`（AGENTS.md 约束；仅允许 `server/src/assets/refs.ts` 既有 warning）。
- 浏览器验证：`npm run dev` 后访问 `localhost:5233`，用共享浏览器页实测交互（节点点击/拖拽/缩放/连线/生成/设为分镜场景图）。

## 常见坑

- **Vue Flow 双向绑定**：`v-model:nodes` 绑 computed 报 readonly 写入错误，用单向绑定 + 事件回写。
- **服务端任务终态**：`completed` / `failed`（无 success/error），轮询按 `completed` 判成功。
- **产物固定文件名**：节点产物统一 `output.{ext}`（原型 `outputExt`），**勿再引入版本号文件名**；历史由服务端 history 目录管理，前端不要读写 `config.current`/`config.history`（旧字段仅兼容读取）。
- **生成节点上传走 `/api/canvas/upload`**：`useCanvasUpload` 按 `isCanvasNodeOutputPath(dest)` 自动选择端点（画布节点固定产物路径 → canvas 上传端点，其余 → `/fs/upload`）；上传目标必须是固定产物路径，服务端先归档旧产物再覆盖；图片统一落盘 `output.jpg`（png/webp 原样写入），视频仅接受 mp4；前端与服务端两处路径正则（`paths.ts: isCanvasNodeOutputPath` 与 `canvas-upload.ts: assertCanvasNodeOutputPath`）须同步修改。
- **节点展示用 `output` prop**：AssetCanvas 按固定路径 + node-info mtime 推导并下发给节点主体/编辑器（`outputOf`）；组件内优先 `props.output`，`config.current` 仅作旧数据回落。
- **预览 watch 需同时监听 path 与 token**：固定路径产物每次重新生成路径不变，预览 URL 只由 token（产物 mtime）区分；节点主体若只 `watch(currentPath)`，新产物覆盖后不会刷新 URL、浏览器命中旧缓存——必须 `watch([currentPath, currentToken])`（实测踩坑，4 个节点主体均已按此实现）。
- **输入预览 URL 必须以源资产 mtime 作缓存键**：编辑器内对连接输入（图片/视频/音频）构建预览 URL 时，必须 `buildPreviewUrl(project, path, version)`——`version` 为来源节点的产物 mtime（`useCanvasNodeOps` 的 `withVersions` 已把 mtime 附到 `CanvasInputInfo.version`）。**不要漏传 version**：漏传时 `buildPreviewUrl` 回退 `?t=Date.now()`，每次配置修改（如编辑提示词）引发的重渲染都会重建缓存键，浏览器会把全部输入媒体当作新资源重新下载（浪费带宽），且 `<img>/<video>/<audio>` 因 src 变化被重建导致配置组件闪烁。
- **配置双向同步**：editor 内 `config.workflowParams ↔ 本地 ref` 双 watch 必须加 JSON 相等性守卫，否则无限循环。
- **尺寸组件回显禁止用未加载完成的能力清单钳制**：`WorkflowSizePicker` 的 `sizeCapabilities` 来自 `currentImpl?.capabilities?.size`，而工作流列表是 `getWorkflows()` **异步**拉取的；拉取完成前该 prop 为 `undefined`，`normalizeSizeCapabilities` 会回退成**默认全量清单**（`16:9/4:3/1:1/3:4/9:16/auto` + `360P/720P/1080P/2K/4K/auto`），此时若把已保存的 `config.sizeConfig` 钳制到该清单，合法档位会被改错（如 Seedream 的 `3:2` → `16:9`、`1K` → `360P`，而宽高不参与钳制所以数值仍正确——正是「刷新后比例/尺寸档与保存值不符、分辨率数值却对」的成因）。组件内以 `echoState` 保存**未钳制的回显原值**，能力声明变化时**始终从原值重新推导**（勿在已钳制结果上二次钳制，否则错值被固化）；能力未知（`sizeCapabilities == null`）时一律不钳制、原样回显，当前值不在选项内时补进按钮组末尾。
- **钳制结果不自动写回配置**：能力声明变化只更新展示，**不得 `emit` 持久化**——静默改写用户已保存的 `sizeConfig` 会把上一步的错值固化进 `canvas.json`；只有用户主动点选档位/改宽高时才写入（画布两个生成编辑器切换工作流类型或实现时本就会 `sizeConfig: undefined` 重置，不会提交越界档位）。
- **服务端尺寸解析只有一处权威：`server/src/workflows/size.ts`**。工作流实现**禁止再自写一套尺寸优先级**——历史上 Bridge 文生图/图片编辑自写 `vars.width/height → projectConfig`，漏读 `ctx.sizeConfig`，导致画布图片节点配置的 16:9 / 2K 被静默换成项目尺寸 1920×1080（且测试用例上下文没有 `sizeConfig` 字段，没拦住）。新增/修改任何「按用户选择的尺寸产出」的工作流实现时：
  1. 用 `resolveSpecifiedGate(sizeConfig, legacyGate, legacyDefault)` 取旧版 `enable_specified_size` 门控四态——`legacyDefault` 显式声明该实现的缺省语义（Bridge 宽松 = true：门控通常不在 Bridge 工作流参数里，旧调用方直接在 vars 给宽高即应生效；Seedream / OpenAI 兼容严格 = false）；
  2. 用 `resolveOutputSize({ sizeConfig, enableSpecified, vars, userParams, fallbackWidth, fallbackHeight })` 取生效宽高（优先级：`sizeConfig` 显式宽高 → 档位换算 → 旧 vars/userParams 宽高 → 项目尺寸）；
  3. 尺寸参数声明复用 `SIZE_PARAMS`（不要在实现里重复写 `enable_specified_size/width/height` 三项）；
  4. **测试必须喂 `sizeConfig`**：只测 `vars.width` 会漏掉画布这条主链路（画布节点只提交 `params.sizeConfig`，vars 里没有宽高）。服务端换算依赖 `size.ts` 的档位表，新增比例/分辨率档时**前端 `frontend/src/utils/workflowSize.ts` 与后端 `server/src/workflows/size.ts` 两处都要改**；档位基准值**恒为输出短边**（横屏落在高、竖屏落在宽），且各档 base 是**业务确认的标准短边、不是统一倍数公式**——`2K` 的 base 是 **1440**、`4K` 是 **2160**、`8K` 是 **4320**（K 档数字只是档位称呼）。把 base 当作宽度会让竖屏算出 `2560x4551` 这类超大图（9:16 / 2K 的历史成因）。
- **`readFs` 对 `.json` 返回反序列化对象**：加载 `canvas.json` 需同时兼容 string 与 object 两种形态。
- **eslint computed 副作用**：`vue/no-side-effects-in-computed-properties` 禁止在 computed 内写缓存/状态，改用 `watch`。
- **面板定位走 `canvas/panelPlacement.ts`**：配置面板定位是纯几何函数（含单测），组件只负责测量「画布可视区 `flowEl.clientHeight/Width`、面板高度 `panelEl.offsetHeight`、节点标题条高度 `.canvas-node__header`」后传入。**不要退回「放不下就钳到视口内」的旧逻辑**——那会让面板盖住整个节点。要点：方向优先级 下→上→右→左；「可行」要求按原始高度完整可见且不遮挡节点（含标题条）；左右贴靠宽度下限 280px、高度下限 240px，且**不与节点垂直居中**（顶边对齐节点顶边、下方空间不足才改底边对齐，避免白白压缩高度）；可行候选择优＝不遮标题条 → 不裁切 → **不收窄高度** → **宽度达到期望下限（`sideMinWidth`，组件按下限保护同一个值传入）** → 压住其他节点最少 → 方向优先级（下方需收窄而左右能保持完整高度时选左右）；**面板高度必须测「自然高度」，且测量宽度必须固定为设计宽度**（测量时临时移除面板与内容区的内联 `max-height`，并临时把两者宽度置为 `min(设计宽度, 可视区宽度-16)`，测完同任务内还原）。漏掉前者会读到被钳制的高度形成压缩锁死；漏掉后者会形成**方向闪动**——实测高度随贴靠方向变化（收窄→换行变高→改到上方→恢复设计宽度→变矮→又判定右侧可行），面板在节点右侧与上方之间以帧级频率抽搐（见 [editor-panel.md](./editor-panel.md) 测量口径）。**定位函数的输入必须与「本次采用的贴靠方向」无关**，否则任何「定位→尺寸→实测→定位」的链路都会自激。降级排序（无可行候选时）＝不遮标题条 → 不裁切 → **不收窄（都只能收窄时取可见高度更大者）** → 压住其他节点最少 → 方向优先级，其中「不收窄」必须排在障碍物重叠之前，否则会把面板塞进很矮的位置并诱发方向抖动；（`obstacles` 由 AssetCanvas 传入其余节点）；滞回仅在「上次方向仍可行且完全同分」时保持，方向由组件 `watch(placement)` 记录并写回 `previousSide`。**高度上限要同时下发到面板与内容区**（`.canvas-node-editor-panel__body` 的 `max-height`），否则面板内容变化长高后会越出定位位置压住节点。改算法务必同步更新 `panelPlacement.test.ts`（含「滞回稳定：回传 previousSide 结果不变」不变量测试）。
- **切换画布必须显式 fitView**：`fitViewOnInit` 只在 Vue Flow 首次初始化时跑一次，切换分镜/场景节点换了但视口仍停在旧坐标。`fitView` 在节点尚未测出宽高或容器尺寸为 0（画布 Tab 隐藏）时返回 `false`，必须 pending 后由 `onNodesInitialized` / ResizeObserver 再试，且用世代号丢弃过期请求；不要在每次 resize 时无条件 fit，会抢用户手动平移/缩放。
- **任务状态来源**：工作流任务本地轮询 `/api/workflow/tasks/:id`；ffmpeg/LLM 任务由统一任务注册表经 WS 广播驱动（`taskSocket`）。画布切换只需 `gen.switchTarget()` + `gen.restore(knownNodeIds)`（**不要**再引入 localStorage 任务记录，已移除）；恢复数据源为注册表 + SQLite 工作流任务补查（见 [task-architecture.md](./task-architecture.md)），画布定位须随提交携带（工作流走 `params.nodeId`/`params.canvas`）。
- **连线右键**：`@edge-context-menu` 需手动 `event.preventDefault()` 阻止浏览器默认菜单叠加。
- **节点缩放**：核心包不含缩放组件，控制点由独立包 `@vue-flow/node-resizer` 提供；缩放中的实时尺寸只写在 Vue Flow 内部节点样式上，业务 `width/height`（及左侧/上侧缩放时的 `x/y`）在 `resizeEnd` 事件统一回写 store——勿在 `resize` 事件里回写，会高频压入撤销栈并反复触发保存。
- **缩放控制点显隐**：`NodeResizer` 的 `isVisible` 需包含「缩放中」状态（悬浮/选中/缩放中任一为真），否则拖出节点边界触发 mouseleave 卸载控制点会中断缩放。
- **滚轮缩放豁免**：Vue Flow 按 `noWheelClassName`（默认 `nowheel`）判定是否拦截滚轮缩放；文本节点 textarea 必须带 `nowheel` 类才能在节点内滚动文本。同理节点拖拽豁免用 `nodrag`（textarea 上拖拽选择文本不移动节点）。
- **剪贴板粘贴**：文件/文本粘贴统一在全局 `paste` 事件中处理（读 `clipboardData.items` 与 `text/plain`，优先级：**节点复制标记 > 文件 > 文本 > 画布内部复制的节点**）。复制节点（`copyNode`）会把「标记 + 节点 JSON」写入系统剪贴板（覆盖旧内容），因此粘贴节点不会被剪贴板中残留的旧文本/文件抢占；标记在 `onPaste` 中**最先**识别（在输入框焦点判断之前，防止标记 JSON 被原生粘贴插入输入框，输入框内粘贴标记仅吞掉不粘贴节点）。`Ctrl+V` 的 keydown 分支**不能 `preventDefault`**（会阻止浏览器派发 paste 事件），仅在剪贴板为空时用宏任务兜底粘贴内部复制的节点。焦点在 INPUT/TEXTAREA 内放行原生粘贴（粘贴进文本节点/编辑器输入框）。
- **加载节点上传**：统一走 `useCanvasUpload`（节点 body/编辑器 `upload-file` 事件与粘贴均经它）。进度来自 `client.uploadFs` 的 `onUploadProgress`（浏览器 XHR upload 事件，纯前端能力，服务端无需改动）；粘贴媒体会**先创建空加载节点再上传**（进度显示在节点上），因此粘贴上传完成的撤销是两步（①撤 assetPath ②撤节点）。本地回环上传很快，小文件进度条可能一闪而过属正常现象。
- **上传进度实时性**：进度经 Vue `reactive` 代理写回（`states[nodeId]` 返回代理），**勿直接修改捕获的原始 state 对象**（不触发响应式更新，进度条不刷新）。
- **上传并发与日志**：同一节点上传进行中再次点「上传」会被忽略（**不中止进行中的请求**）——大文件请求中途被 abort 后，keep-alive 连接复用时残留字节可能污染下一个请求的 multipart 流，服务端解析出畸形字段（如 `Unexpected field`）；该场景服务端会打印 `[fs-upload] 上传失败` 日志并返回友好文案。接口异常统一打日志：前端 axios 响应拦截器（非 2xx 打印 `[api]` 日志，HEAD 404 存在性探测除外）+ 上传组合式 `console.error`；服务端 multer 错误分支 `console.error`。
- **轮询状态会级联重置连线/节点动画**：生成轮询每 tick 都整体重写 `statusByNode[nodeId]`（`lastLog` 变化），画布模板读到它必然重渲染并产生**新的插槽函数引用**。若把「运行中节点集合」等派生集实现为 computed，每次重算返回新 Set 实例 → `flowEdgeList` 重算出新数组 → Vue Flow 触发 `setEdges` 整体重建边对象 → EdgeWrapper 重渲染时以**已变化的插槽函数**作为组件类型（源码 `h(slots['edge-default'], …)`），Vue 判定为不同组件而 remount 插槽子树——连线箭头动画（`offset-path` 移动）被反复归零，节点脉冲动画同理。**派生集必须用 `watch` + 内容相等性守卫维护实例稳定**（内容不变则不替换 Set，见 AssetCanvas 的 `runningNodeIds`），轮询期间下游 computed 全部命中缓存零重算。
- **连线箭头动画时长不能写死**：箭头以 `offset-path: path(<连线 d>)` + `offset-distance: 0%→100%` 驱动，而 `offset-distance` 是**弧长百分比**——固定 `animation-duration` 会让线速度 = 弧长/时长 随连线长度线性增长，长连线箭头快到肉眼无法观察（3000px 的线约 2100px/s）。必须走 `canvas/edgeFlow.ts`：解析贝塞尔弧长得弧长 → `duration = max(弧长/EDGE_FLOW_SPEED, 下限)`、`count = clamp(round(弧长/EDGE_FLOW_ARROW_SPACING), 1, EDGE_FLOW_MAX_ARROWS)`、`delayStep = duration/count`（负 `animation-delay` 等距预分布），由 AssetCanvas 的 `edgeArrows()` 渲染并内联注入。**时长不可每帧重算**：浏览器按 `进度 = 已过时间/时长` 重算位置，拖动节点时几何每帧变化会让箭头瞬间跳位——用 `createEdgeFlowCache`（弧长变化 <15% 且箭头数量未跨档则复用旧参数）抑制抖动；箭头数量变化时用**索引 key** 让已有箭头被 patch 而非 remount，否则动画被重置。改动画观感只需调 `EDGE_FLOW_SPEED`（速度）与 `EDGE_FLOW_ARROW_SPACING`（密度）两个常量。
- **删除类操作**：必须走 `confirm` 工具弹窗确认（AGENTS.md 约束）。
- **持久分组节点必须 `pointer-events: none !important`**：Vue Flow 的框选要求指针按下时 `event.target` 恰为 `.vue-flow__pane`；Vue Flow 会给带节点点击监听的节点内联 `style="pointer-events: all"`，**普通样式规则压不过内联样式**，因此分组节点 wrapper 的 `pointer-events: none` 必须带 `!important`（子元素标题条/拖动条/缩放控制点各自声明 `auto` 覆盖继承值）。漏写会让组内 Ctrl+拖拽框选完全失效。
- **持久分组尺寸经 `style` 下发**：NodeResizer 缩放时会把尺寸写进 Vue Flow 内部节点 `style`；分组节点对象若只带 `width`/`height` 字段而不带 `style`，`Object.assign` 不会清除内部残留 style，store 回写（缩放结束/撤销）后框体渲染尺寸与数据不一致。与真实节点一致地传 `style: { width, height }`。
- **持久分组拖动不能用原生拖动**：Vue Flow 原生拖动会同时移动全部选中节点，分组若用原生拖动会导致「节点被移动两次」。分组节点 `draggable: false`，用 `useCanvasGroups` 的自定义拖动（拖动中 `updateNode(id,{position})` 只做视图跟随、不写 store，结束经 `store.moveEntities` 一次性回写保证单次撤销）。
- **复制粘贴的落点必须走 `canvas/pastePlacement.ts`（零重叠 + 净距硬约束）**：分组成员关系由几何实时派生，副本与原件矩形一旦重叠，`collectDragFollowSet` 会把对方节点算进跟随集——现象是「拖副本分组把原节点一起拖走、两层节点叠在一起分不开」。**历史故障**：粘贴用固定 30px 偏移，而分组框通常几百像素宽，副本 100% 压住原件。统一入口 `clipboardPlacementOffset`（首选原内容包围盒右下方向外一个身位 + 30px 间隙，被占用则沿 +x 逐级探测、再换泳道、最后兜底放到阻挡内容右侧；判定带 `PASTE_CLEARANCE` 净距，禁止贴边紧邻），**新增任何「复制出第二份/插入内容」的路径都必须复用它**（粘贴走 `store.pasteNodes`；蓝图插入若目标处已有内容也要先避让）。回归用例见 `pastePlacement.test.ts` 与 `useCanvasStore.test.ts` 中「拖副本分组不再带走源节点」。
- **粘贴副本落在视野外才对准视口**：`AssetCanvas.revealPastedEntities` 用 `fitView({ nodes: [新节点…新分组] })` 对准副本，但 `fitView` 只纳入**已测出宽高**的节点（粘贴后需等待若干帧），必须轮询重试（现为最多 8 次 × 40ms）而非单次调用，否则偶发返回 false 只能提示用户手动缩小；副本只要露出一角就不动视口（不打断用户操作）。
- **提交信息**：中文提交信息在 PowerShell 下用 `-m` 会乱码，用 UTF-8 临时文件 `--amend -F` 方式提交。
- **ffmpeg 命令必须与执行分离**：新增本地 ffmpeg 操作时，模块导出 `buildXxxCommand()`（探测 + 校验 + 装配，返回 `assets/ffmpeg-command.ts` 的 `FfmpegCommandSpec`），由 `tasks/ffmpeg-executor.ts` 统一 `save()` 并接管事件——直接在模块内 `save()` 会绕过执行器，导致无进度、无法中断（见 [task-architecture.md](./task-architecture.md)）。
- **filter_complex 的 concat 输入标签**：必须写成 `[v0][a0][v1][a1]concat=n=2:v=1:a=1[vout][aout]`（标签串联），漏写或只写 `concat=...` 都会让 ffmpeg 报 `No output pad can be associated to link label` / `Cannot find a matching stream`。
- **fluent-ffmpeg `inputOptions` 附着于最近一次 `input`**：追加 lavfi 静音源须 `inputOptions([...])` 与 `input('anullsrc=...')` 成对调用；静音源输入下标 = 段数 + 已追加的静音源数。
- **任务状态只有两个来源**：工作流任务本地轮询 `/api/workflow/tasks/:id`；ffmpeg/LLM 任务由统一任务注册表经 WS 广播驱动（`taskSocket`）。**不要再引入 localStorage 任务记录**（已移除）；画布恢复 Loading 读注册表 + SQLite 工作流任务（两者都要求任务携带 `nodeId`/`canvas`，新增任务类型勿漏传）。
- **配置面板加宽必须朝「远离节点」的方向长**（`CanvasEditorPanel` 的宽度下限保护）：定位算法在上下放不下时会贴靠左右侧并把宽度收窄到 `PANEL_SIDE_MIN_WIDTH`（280px）。给某类节点加下限（如「图片修剪与扩展」的框选器需要 ≥440px）时，**不能只提高 `min-width`**——面板是按某个侧边锚定摆放的，浏览器会朝另一侧长出去、把面板横向盖到节点上（破坏「面板永不遮挡整个节点」的保证）。正确做法见 `panelStyle`：贴靠左侧时以**右边缘**锚定、加宽往左长；贴靠右侧时以左边缘锚定；并依次用「可视区左/右缘」与「节点近侧边缘」两个上限钳制，放不下就退回 `min(result.width, PANEL_MIN_WIDTH)`，绝不越过节点。
- **宽度下限只做「加宽」是不够的，还得参与「选方向」**：`panelStyle` 的加宽受可视区与节点边缘钳制，节点靠近画布可视区右缘时右侧只剩三四百像素，加宽被钳回原宽度——设计宽度 560px 的面板实际渲染成 400px（实测：节点右缘距可视区右缘 358px）。两处必须同时改：① `computePanelPlacement` 新增 `sideMinWidth` 输入（组件传「设计宽度 ∩ `PANEL_MIN_WIDTH` ∩ 可视区可用宽度」，与 `panelStyle` 的加宽同一个值，避免「按 560 选方向、按 440 加宽」的口径分叉），作为**同级排序项**排在「不收窄高度」之后；② `panelStyle` 的三个钳制按方向区分（贴左时加宽可能把左缘推出可视区，此时要**收回宽度**而不是靠末尾的 `left` 钳制「修正」——那会把右边缘推回节点里）。
- **约束条件的适用范围要和几何事实一致**：「不得越过节点近侧边缘」只在面板**贴靠节点左右侧**时成立；上下方位（below/above）面板整体在节点上下方，横向加宽与遮挡无关。曾把该钳制无条件套在所有方向上，退化成「宽度 = 节点右边缘 − 面板左边缘」这种与遮挡毫不相干的截断（实测：面板在节点下方时设计宽度 560px 被截成 400px，框选器跟着缩水——定位正常却宽度失守）。
- **`v-menu` 激活器插槽里的动态内容不会随父组件重渲染**：`#activator` 插槽由 VMenu 渲染，父组件重渲染时该插槽被标记为 stable，子组件不会重新执行插槽函数 → 插槽内的 `:style` / `:title` 等绑定停在**首次渲染的值**（实测：改背景色后调色盘与舞台都已生效，唯独色块仍是旧颜色；菜单开合时因 VMenu 自身状态变化才会补上）。需要动态显示的激活器一律**用 `:activator="选择器"` 绑定自家模板里的普通元素**（如 `:activator="'#' + swatchId"`，id 由节点 id 派生保证唯一），别把动态内容放进插槽。
- **`background-image` 里不能写「位置 / 尺寸」**：`linear-gradient(...), repeating-conic-gradient(...) 50% / 8px 8px` 这种 `position / size` 语法**只在 `background` 简写里合法**，塞进 `background-image` 会让整条声明失效且浏览器静默丢弃（实测：色块的 `style` 属性干脆是空的、`getComputedStyle().backgroundImage` 为 `none`，颜色永远看不出来）。多图层要分开写 `backgroundImage` + `backgroundSize`（`'auto, 8px 8px'`）。
- **叠加层几何必须只有一个尺寸来源**：任何「展示组件 + 叠加交互层」的组合（如「图片修剪与扩展」的 `ImageCropStage` + 手柄层），**禁止一边用实测 `clientWidth/clientHeight`、另一边用 CSS `aspect-ratio` 推算**——两者在布局尚未稳定时会短暂不一致（实测踩坑：叠加层按 `clientHeight=223` 计算、源图按 `aspect-ratio` 渲染为 167，选区框比源图高 33%，手柄全部错位）。统一做法：**由展示组件测量并通过事件（`rect`）上报唯一的几何矩形**，交互层只用该数据；`ResizeObserver` 负责在容器尺寸变化时重测。给面板/容器设 `min-width` 时同样注意会触发重排，勿在测量的同一帧内读取尺寸。
- **留白舞台必须是源图的「两轴等比放大」，否则纵向留白会被吃成 0**：`ImageCropStage` 把舞台做成 `源图显示尺寸 × IMAGE_CROP_STAGE_MARGIN_FACTOR`（当前留白比例 1 ⇒ 系数 3），所以**舞台宽高比恒等于源图宽高比**，使用方给 `aspect` 传的就是 `srcAspect` 本身（**不要乘系数**）。曾把舞台宽高比写成「源图宽高比 × 系数」，舞台比源图更扁；源图显示高又按「显示宽 ÷ 源图宽高比」推导 ⇒ 恰好等于舞台高，**纵向留白归零**（横向有 45% 留白、上下一点没有，向上/向下拖不出去）。两条口径要一起看：① 使用方传对 `aspect`，两轴留白才相等；② `ImageCropStage` 内部始终**按显示宽推导显示高**（不按舞台高取比例），这是「绝不拉伸」的硬保证——传错 `aspect` 时最坏只是留白不等，图仍不变形。
- **传给 `src-aspect` 的源图宽高比不得「按版式钳制」**：曾把 `srcAspect` 钳制在 `[0.9, 2.4]` 以避免舞台过扁/过高，结果是把 9:16 竖图与 3:1 全景图**压扁/拉长**（实测：1080×1920 的竖图按 0.9 渲染相当于压扁 1.6 倍）。比例只影响舞台外形，不构成任何布局风险——极窄源图得到高舞台（由滚动容器 `max-height` 兜住）、极宽源图得到扁舞台，都是正确结果；需要看清时用显示缩放（滚轮）放大即可。
- **留白拉满后必须给「显示缩放」**：留白比例从 0.45 提到 1（每边留出与源图等大的空白）后，默认缩放下源图只有面板宽度的 1/3，精细拖拽会变难——所以缩放不是可选项。实现要点：舞台宽度 = `缩放 × 滚动容器宽`（`width: zoom*100%` + `aspect-ratio`）⇒ 整块等比放大，外层 `overflow: auto` 承担滚动。**滚轮缩放的滚动位置必须在 `nextTick` 之后再写**：缩放改的是舞台宽度，同一帧内 `scrollWidth` 还是旧值，立刻写 `scrollLeft` 会被浏览器按旧范围钳制（表现为「放大后指针下的内容漂走」）；`anchoredZoomScroll` 负责算值，指针锚定的含义是「缩放前后指针下的那一点内容不动」。滚轮监听用 `@wheel.prevent`（Vue 默认非 passive；Chrome 只对 window/document/body 上的 wheel 强制 passive），并在容器与舞台上加 `nodrag nowheel`，避免 Vue Flow 拦截。**缩放量要按位移取指数映射（`zoomByWheelDelta`）而不是「每事件一档」**：触控板一次滑动会连发几十个 `deltaY = ±3` 的小事件，每事件乘 1.15 会瞬间冲到上限；同时要把 `deltaMode` 归一化成像素（Firefox 默认按行上报，一格 `deltaY = 3`），否则滚轮要滚几十下才动一档。
- **显示缩放必须落在「固定高度的编辑区视口」里**：舞台高度随缩放线性增长（高 = 宽 ÷ 源图宽高比），若让滚动容器跟着内容长高，滚轮缩放会把编辑区、进而把整个配置面板一起撑高——用户看到的是「整个配置面板在缩放」，下方读数/背景色/应用按钮全被推着跑（实测：100% 时面板 401px、缩放到 201% 时内容把面板顶高一大截）。做法：滚动容器**高度由 CSS `aspect-ratio`（= 源图宽高比）给出**（`width: 100%` + `aspect-ratio` ⇒ 恰好容纳 1 倍下的整块舞台），配 `min-height` / `max-height: 60vh` 兜底；缩放只改视口内舞台的尺寸，超出部分由滚动条承担。**不要用「测量舞台宽度再回写高度」**：小数取整差 1px 就会多出一条纵向滚动条，滚动条又吃掉 15px 内容宽 → 舞台变窄 → 算出的高度更小，卡在一个「带滚动条且宽度缩水」的自洽状态里（实测舞台宽度从 544 掉到 529）。容器用 `display: flex` + 子项 `margin: auto` 让内容居中且溢出时仍可完整滚动，子项必须 `flex: 0 0 auto`（默认 `flex-shrink: 1` 会把舞台压回容器宽度，缩放直接失效）。
- **显示缩放不得引入第二套几何**：缩放只改舞台的 CSS 尺寸，拖拽换算仍读 `ImageCropStage` 上报的实测矩形（`stageRect`），因此任意缩放下位移都精确——**不要**按缩放倍率去反算坐标，那等于把「唯一尺寸来源」破坏掉（见上文叠加层那条）。
- **主体无交互的节点卡片不要带 `nodrag`**：`nodrag`/`nowheel` 是「节点内的交互元素」用的豁免类（文本域、输入预览滚动区）。若节点主体本身不可交互（如「图片修剪与扩展」与「加载图片」节点：只显示一张图），把 `nodrag` 加在根元素上会**让节点彻底拖不动**，而正确做法是让图片 `pointer-events: none`（顺带屏蔽原生图片拖动），把指针事件留给节点根元素——这样「点击打开配置面板」与「按住拖动节点」两种交互都保留。
- **纯前端 canvas 生成的节点（图片修剪与扩展）**：不走任务架构（无注册表记录、无中断、刷新后无 Loading 可恢复），产物经 `POST /api/canvas/upload` 落盘（自动归档旧产物）。两个易漏点：① 超尺寸时 `drawImage` **不抛异常而是画出空白**，必须在合成前用 `validateOutputSize` 拦截；② 产物扩展名随 `config.format` 变化，切换后需由 AssetCanvas 静默写回 `config.outputExt` 镜像（与裁剪音频同款），否则刷新后 node-info 会去查旧扩展名。
