# 资产画布功能设计规格

> 状态：设计中（2026-08-03 更新，参考 LibTV 创作画布竞品调研后修订）
> 技术栈：基于 Vue Flow 最新版

## 1. 背景与定位

在**场景详情面板**（`StagePanel`）和**分镜详情面板**（`ScenePanel`）中新增资产画布功能，提供最高自由度的资产生成编排，方便进行文生图、图生图操作。

**定位：迭代工作台，与现有生成入口并存。**
- 每个节点的每次生成都**留痕**（历史版本），可回溯、回滚，迭代成本低；
- 与现有「场景图片」「一键生成」「批量生成」等入口**并存**，画布面向需要自由编排、组合参考图的进阶创作；
- 场景画布产出场景图；分镜画布可复用场景/角色资产作为输入。

### 已确认的设计决策

1. 入口：场景/分镜面板新增「资产画布」Tab，与现有「场景图片」Tab 并存。
2. 多输入：节点支持接受多个节点作为输入；有参考图与无参考图调用不同类型的模型和工作流；v1 只提供**底层工作流操作逻辑**，不做智能推断。
3. 自动搭画布：用户**手动点击触发**，当前只做图生图节点的自动创建。
4. 节点范围：v1 只做图片链路；【生成图片】只接受图片类型输入；连接按**数据类型**校验（ComfyUI 思路），而非固定按节点类型。
5. 不做一键重跑：上游更新只**提示**，由用户手动触发重新生成。
6. 底层存储：`mkdir / rename / delete / upload` 的路径限制从仅 `assert/custom/` 放宽到整个 `assert/` 前缀，以支持画布资产区；另新增 `copy` 端点（详见 §10.4）。

## 2. 入口

- 场景详情面板、分镜详情面板各新增一个「资产画布」Tab，与现有「场景图片」等 Tab 并存。
- 画布内工具栏提供：适应视图（fit）、缩放 +/-、撤销/重做、自动搭画布、节点多选等入口。

## 3. 画布交互

### 3.1 视图操作

- 空白处拖拽：整体平移画布视图
- 滚轮：缩放
- 工具栏：适应视图（fit）、缩放 +/-、重置
- 工具栏「自动整理」：一键自动布局节点，节点较多、排版混乱时使用

### 3.2 节点操作

- 拖拽节点任意移动布局
- `resizeable` 为 true 的节点：右下角拖拽调整大小
- 单击节点：选中，并在**节点下方**展开配置组件（`editorComponent`）
- 删除节点：弹窗确认（沿用 `confirm` 工具，提供标题/内容/确认按钮），确认后删除节点及其所有连线；**不删除**关联的资产文件
- 删除连线：直接删除，不弹窗
- 右键菜单：节点右键弹出快捷操作（重新生成 / 历史版本 / 重命名 / 复制 / 删除）
- 复制 / 粘贴节点：`Ctrl+C` / `Ctrl+V`，`Ctrl+D` 快速复制（含节点配置与连线关系）

### 3.3 撤销 / 重做

- `Ctrl+Z` / `Ctrl+Shift+Z`
- 覆盖：添加/删除节点、建立/断开连线、移动、缩放、自动搭画布
- （配置表单内的文本输入撤销由输入框自身处理，不纳入画布撤销栈）

### 3.4 添加节点

- 双击画布空白处：弹出添加节点对话框
- v1 支持节点：**加载图片、生成图片、文本**
- 首次进入空画布时显示引导提示：双击空白添加节点 / 点击「自动搭建」一键搭建

### 3.5 自动搭画布（手动触发）

- 工具栏「按分镜自动搭建」按钮（分镜画布）/「按场景自动搭建」按钮（场景画布），用户点击后触发，**进入画布不自动执行**，详见第 7 节。

## 4. 节点连接

### 4.1 方向与拓扑约定

1. 节点左侧 = 输入端口（接受其他节点的连接）；节点右侧 = 输出端口（连接其他节点）。
2. 一个节点可连接多个其他节点，也可被多个节点连接（多对多）。
3. 不允许循环连接。

### 4.2 类型系统（ComfyUI 思路）

连接是否允许**由端口的数据类型决定**，而不是由节点类型决定：

```ts
/** 数据流类型 */
type DataType = 'image' | 'text'

/** 端口：节点的输入/输出接口，每个端口有固定类型 */
interface Port {
  /** 端口唯一标识（节点内唯一） */
  id: string
  /** 端口数据类型，连接时校验 */
  type: DataType
  /** 端口显示名 */
  label?: string
}
```

**连接规则**：仅当 `输出端口.type === 输入端口.type`（或类型兼容）时允许建立连接。

v1 端口定义：

| 节点 | 输入端口 | 输出端口 |
|------|----------|----------|
| 加载图片 | — | `image` |
| 生成图片 | `image` × N（N≥0，只接受图片类型） | `image` |
| 文本 | — | `text`（预留，v1 暂无节点接受 text 输入） |

### 4.3 连接交互方式

1. 鼠标悬浮节点时，节点左、右位置出现「+」号手柄；按住「+」拖拽拖出一条曲线。
2. 释放鼠标时：
   - 落在**类型兼容且不会形成循环**的节点上 → 建立连接；
   - 否则 → 取消本次连接。
3. 拖拽过程中，类型不兼容或会导致循环的节点**置灰/显示禁止**样式，避免无效操作。
4. 断开连线：拖住已有连线端点拖到空白处；改连：拖到另一个兼容节点（目标悬停高亮）。

### 4.4 连接数据

```ts
interface CanvasConnection {
  id: string
  fromNodeId: string
  fromPortId: string
  toNodeId: string
  toPortId: string
}
```

## 5. 节点的定义

### 5.1 节点原型

```ts
interface NodePrototype {
  /** 该节点类型的唯一标识，代码中硬编码 */
  id: string

  /** 节点名称（方便用户阅读） */
  name: string

  /** 输入端口定义（可接受的连接类型由此决定；取代原规划的 acceptNode 固定节点类型列表） */
  inputPorts: Port[]

  /** 输出端口定义 */
  outputPorts: Port[]

  /** 该类型节点是否允许用户自由缩放大小 */
  resizeable: boolean

  /** 渲染该类型节点卡片本身的Vue组件。如文本节点直接就是一个可编辑的文本编辑框，图片节点就是一个图片。组件内需要能拿到节点实例对象。 */
  bodyComponent: 待定

  /** 用户对该节点实例操作配置的Vue组件，当节点被用户点击后会渲染在节点下方的组件。为空时表示该节点不需要用户操作配置组件。组件内需要能拿到节点实例对象。*/
  editorComponent?: 待定
}
```

> **变更说明**：原规划用 `acceptNode: string[]` 按节点类型限制连接；现改为**类型化端口**（ComfyUI 思路）——节点声明输入/输出端口及数据类型，连接按类型校验。后续新增节点类型时连接逻辑无需改动。

### 5.2 节点实例

```ts
interface NodeHistoryAssert<T> {
  assert: T
  date: Date
}

/**
 * 节点实例
 */
interface NodeInstance<T> {
  /** 实例唯一标识，系统随机生成 */
  id: string

  /** 触发该节点的资产生成动作，生成完成后资产可被 getAssert 方法获取到。*/
  generateAssert(): T | Promise<T>

  /** 中断资产生成 */
  interruptGenerate(): Promise<void>

  /** 获取该节点的资产生成状态（含失败态） */
  getGenerateStatus(): Promise<{ status: 'pending' | 'free' | 'error', progress?: number, lastLog?: string, error?: string }>

  /** 从该节点实例中提取资产资源。如果节点没有资产或资产为生成则返回undefined */
  getAssert(): T | undefined | Promise<T | undefined>

  /** 获取该资产的url，用于在浏览器上展示 */
  getAssertUrl(): string

  /** 获取该节点实例的历史资产 */
  getHistoryAssert(): NodeHistoryAssert<T>[] | Promise<NodeHistoryAssert<T>[]>

  /** 获取该节点实例的元数据 */
  getMetadata(): NodeMetadata
}

/**
 * 节点实例元数据
 */
interface NodeMetadata {
  /** 节点名称，用户可修改；画布内唯一，为空则取 NodePrototype 的 name。节点卡片上常显名称 + 类型图标 */
  name: string

  /** 在画布中的x坐标 */
  x: number

  /** 在画布中的y坐标 */
  y: number

  /** 在画布中的宽度 */
  width: number

  /** 在画布中的高度 */
  height: number

  /** 已连接到该节点的其他节点实例的id（端口级细节见 CanvasConnection） */
  inputs: string[]

  /** 用户在该节点配置的其他数据。如：图片节点允许用户输入图片生成/编辑的提示词prompt、选择用于生成资产的工作流id、配置的工作流参数等 */
  config: { [key: string]: unknown }
}
```

## 6. 各节点描述

### 6.1 加载图片

- 新增后是空白状态，有 2 个按钮：【上传图片】和【选择资产】
  - **上传图片**：用户上传图片到该分镜/场景的自定义资产中，并在上传后自动选择上。
  - **选择资产**：通过对话框打开资产选择器，选择除了画布资产以外的所有图片类型资产。
- 完成资产选择后，节点内显示图片。
- 不需要执行资产生成动作。
- 后端获取资产时直接拿到 File 对象。
- 输出端口：`image`。

### 6.2 生成图片

- 新增后是空白状态。
- 输入端口：`image` × N（N≥0，只接受图片类型输入）；输出端口：`image`。

配置组件（`editorComponent`）包含：
1. 节点名称（画布内唯一）
2. 提示词 prompt（文本框）
3. 工作流选择：
   - 无图片输入 → 默认 `text-to-image`（文生图工作流）
   - 有图片输入（≥1）→ 默认 `image-edit`（图片编辑工作流）
   - **底层策略**：仅提供上述默认建议，用户可手动改选任意可用工作流；v1 不做智能推断
4. 工作流参数：复用现有 `WorkflowParamsForm`，按所选工作流 schema 渲染参数
5. 执行生成按钮 / 中断按钮
6. 生成状态：loading、进度、最后一条任务日志
7. 历史资产列表（可查看 / 回滚）
8. **桥接视频生成**：分镜画布提供「设为分镜场景图」按钮（场景画布为「设为场景图」），将当前结果写入该分镜/场景的场景图资产，一键进入现有「视频生成」流程
9. **候选方案生成**：一次生成多个候选结果（复用批量生成思路），从候选中挑选保存

输入图处理（v1）：
- 所有图片输入一律作为**参考图**传入所选工作流；
- 配置中列出当前输入图（缩略图），可预览来源节点；
- 输入图**顺序可拖拽调整**（顺序影响工作流中的参考图排列，进而影响生成结果）；
- 不做权重、区域控制等高级配置（v1）。

### 6.3 文本

- 画布上的可编辑文本块，用作提示词草稿 / 备注。
- 输出端口：`text`（预留类型）。
- v1 尚无节点接受 `text` 输入，因此不可连接；连接逻辑已按类型系统就绪，未来扩展 prompt 片段拼接时无需改动框架。

## 7. 自动搭画布

**触发**：画布工具栏按钮，用户手动点击；进入画布不自动执行。

**分镜画布（按分镜搭建）**：
1. 读取分镜 `stage.json` 中引用的角色、场景；
2. 为每个被引用的角色/场景自动创建「加载图片」节点，并自动选中对应资产（角色外观资产 / 场景资产）——作为**锚点节点**；
3. 自动创建一个「生成图片」节点，并**自动连接**所有锚点节点作为其输入（即图生图节点）；
4. 自动布局：锚点节点在左，生成节点在右；
5. **预填提示词**：将分镜 `overview.json` 的画面描述（visual）预填为生成节点 prompt 初稿，可再追加角色 `appearance.md` 内容，用户在此基础上修改，不必从空开始。

**场景画布（按场景搭建）**：读取场景引用的资产，按同样规则创建锚点节点 + 连接一个「生成图片」节点；prompt 预填子场景画面描述。

**幂等策略**：已存在且未被删除的锚点/生成节点不重复创建；再次点击时仅补充缺失的引用节点。

**范围**：v1 只做「图生图节点」的自动创建（锚点节点 + 已连接输入的生成图片节点）；不自动创建文生图、文本等其他节点。

## 8. 生成状态与上游更新提示

### 8.1 生成状态

- 节点处于资产生成中：显示**统一的 loading 效果** + 进度 + **最后一条资产生成任务的日志**。
- 可中断（`interruptGenerate`）。
- **失败态**：生成失败时节点显示错误状态与错误详情，并提供**重试**按钮（重新执行生成）；失败不产生历史版本。
- 多节点并发生成时，工具栏/顶部显示任务队列概览，避免误以为卡死。

### 8.2 上游更新提示（不做一键重跑）

- 上游节点重新生成（产生新版本）后，其**下游节点**显示「上游已更新」角标/徽标；
- 仅提示，**不自动重跑**；用户点击该下游节点的生成按钮手动重新生成；
- 下游重新生成完成后提示消失。

## 9. 资产生命周期

- 每次生成 = **新增一个历史版本**，不静默覆盖；
- 节点上显示当前版本信息，可打开历史列表查看 / 对比 / 回滚；
- **版本对比**：历史列表支持 A/B 并排对比，直观比较两版生成结果；
- 删除节点与删除资产文件**解耦**，默认只删除节点；
- 生成成功后，画布资产自动出现在该场景/分镜的自定义资产中，供「场景图片 / 视频生成」等后续环节复用；
- **桥接现有流程**：节点结果图可一键「设为分镜场景图 / 设为场景图」，直接进入现有「视频生成」流程（详见 §6.2）；
- **画布复制 / 复用**：支持将当前画布**复制到其他分镜**，或**从上一分镜复制画布**（同一场景反复出镜时复用，无需重搭）。

## 10. 数据持久化与资源引用（实现要点）

### 10.1 核心原则：统一项目相对路径引用

- 所有节点引用的资产一律存**项目相对路径**（如 `assert/character/张三/appearance.jpg`），**不存 URL**；
- 预览 URL 由前端运行时拼接：`/api/fs/${project}/${relPath}?t=${Date.now()}`（沿用现有约定，时间戳防缓存）；
- 服务端解析路径时统一校验，防止 `..` 逃逸（沿用 `resolveProjectAssertPath` 模式）。

### 10.2 持久化模型：定义与产物分离

`canvas.json`（画布定义，前端写）与生成产物（磁盘文件，引擎写）**分开保存、分开写入**：

```
prompt/stage/{场景名}/canvas.json        ← 场景画布定义
prompt/scene/{集数}/{分镜}/canvas.json    ← 分镜画布定义
assert/{scope}/canvas/{nodeId}/          ← 生成产物（scope = stage/{场景名} 或 scene/{集数}/{分镜}）
  v1.jpg  v2.jpg  v3.jpg
```

**版本号客户端预计算**：工作流 run 接口要求先给 `outputPath`，因此前端在发起生成前按「历史长度 + 1」算出 `v{n}`，把 `assert/{scope}/canvas/{nodeId}/v{n}.jpg` 传给引擎；成功后把该路径追加进 canvas.json 的历史。引擎保持“傻瓜写盘”，canvas.json 是唯一索引：

- 每次生成 = 新文件，**天然不覆盖**、无缓存问题；
- 失败时仅索引未更新，残留文件可清理。

**canvas.json schema**（节点只存数据；`generateAssert` 等是前端运行时行为，不持久化）：

```ts
interface CanvasData {
  version: 1                    // schema 版本，读取时迁移
  kind: 'stage' | 'scene'       // 场景画布 / 分镜画布
  nodes: CanvasNodeData[]
  connections: CanvasConnection[]   // 见 §4.4
  createdAt: string
  updatedAt: string
}

interface CanvasNodeData {
  id: string
  prototypeId: 'image-loader' | 'image-generate' | 'text'
  name: string
  x: number
  y: number
  width: number
  height: number
  config: Record<string, unknown>
}

// 加载图片 config: { assetPath: 'assert/character/张三/appearance.jpg' }
// 生成图片 config: {
//   prompt: string
//   workflowId: string
//   workflowImpl?: string
//   workflowParams: Record<string, unknown>
//   current: { version: number; path: string; date: string } | null
//   history: { version: number; path: string; date: string }[]
// }
```

canvas.json 读写**复用现有 `/fs` API**（`prompt/` 前缀可写；读 .json 自动反序列化），无需新端点。

### 10.3 不同来源资源的引用与预览

| 来源 | 引用（存 config） | 预览 | 生成时 |
|------|------------------|------|--------|
| 资产库（角色/场景/自定义） | `assert/...` 相对路径 | `/api/fs/:project/{path}?t=` | 相对路径作为输入参数传给引擎 |
| 画布生成产物 | `assert/{scope}/canvas/{nodeId}/v{n}.jpg` | 同上 | 预计算 outputPath |
| 用户上传 | 先落盘再按路径引用 | 同上 | 走路径 |
| 跨画布引用（场景画布产物 → 分镜画布） | 场景画布产物路径（普通文件） | 同上 | 走路径 |

- 前端统一封装预览工具 `useCanvasAssetUrl(relPath, version)`，版本切换时 `t` 变化即刷新缓存；
- 所有 `<img>` 加 `@error` 兜底显示占位（无资产 / 生成中 / 文件失效）；
- **节点从不直接持有 File/Blob，只持有路径**——上传先落盘到自定义资产区（`assert/custom/`，沿用规格 §6.1），再被节点引用。

### 10.4 后端 API 变更

**决策（已确认）：放宽 `fs.ts` 的 `mkdir / rename / delete / upload` 限制**，从仅 `assert/custom/` 放开到整个 `assert/` 前缀，以支持画布资产区（`assert/{scope}/canvas/`）的创建 / 删除 / 上传。校验规则不变：路径必须位于 `assert/` 且不逃逸项目根。

| 操作 | 现状 | 变更 |
|------|------|------|
| 读写 canvas.json | `/fs` 通用读写（prompt/ 可写）✓ | 复用，无需改动 |
| 生成产物落盘 | 引擎直接写 assert/ 任意路径 ✓ | 无需改动 |
| 上传 | 仅 `assert/custom/` | **放宽到 `assert/`**（决策） |
| mkdir / rename / delete | 仅 `assert/custom/` | **放宽到 `assert/`**（决策） |
| **copy（新增，必需）** | 无 | **新增 `POST /api/fs/:project/copy`**（源 / 目标均在 `assert/` 下） |

> **为何仍需要 copy**：`rename` 是移动，而「设为分镜场景图」（产物复制到场景图位置，原文件保留）和「复制画布到其他分镜」（复制整个 canvas 资产目录）都需要**复制**。copy 端点放在 `fs.ts` 与 rename / delete / upload 并列，校验规则一致。

### 10.5 生成调用链（前端）

```
generateAssert()
  → 解析输入节点 → 相对路径数组 inputImages
  → 计算 outputPath = assert/{scope}/canvas/{nodeId}/v{n}.jpg
  → POST /api/workflow/run
      { project, workflowId, impl, params: { vars, userParams: { prompt, inputImages, ... }, outputPath } }
  → 轮询 GET /api/workflow/tasks/:taskId 与 /log（进度 + 最后一条日志）
  → 成功后更新 canvas.json 的 history
```

### 10.6 健壮性

- 失效引用：资产被删 / 生成失败 → 前端 `<img @error>` 占位 + 生成前 `existsFs` 预检并给出明确报错；
- 幂等：版本号递增保证不覆盖；
- 防逃逸：所有路径服务端校验（沿用现有模式）；
- 迁移：`canvas.json.version`，读取时按版本迁移；
- 保存：canvas.json 防抖自动保存 + 脏标记（切换面板时提示未保存变更）。
